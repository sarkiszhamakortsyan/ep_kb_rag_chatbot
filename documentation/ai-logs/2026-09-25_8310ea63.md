**Endpoints** (Swagger documentation at http://localhost:8080/api/v1/... and `/docs` on the backend):

| Endpoint | What it does |
|---|---|
| `GET /api/v1/health` | Always returns 200, with status `starting` / `ok` / `degraded`, whether the index is ready, and the Ollama status |
| `GET /api/v1/providers` | Lists the enabled models and whether each is usable. Without a key, Claude is shown as unavailable with the reason |
| `POST /api/v1/chat` | `{message, conversation_id?, options: {provider?}}` → answer, citations, whether it refused and why, token usage, timings |
| `POST /api/v1/chat/stream` | The same answer as a stream of events: `meta` (ids and candidate sources) → `token`… → `done` (full result), or `error` |

**How it behaves:**
- **Errors:** every error has the same shape, `{"error": {"code", "message"}}`. A bad request returns 422, an unknown or disabled provider 400, an index that's still loading or a provider that's down 503, and a provider error 502.
- **Unsupported options:** anything other than `provider` inside `options` (for example `language`) is rejected with 422 rather than silently ignored. Language and detail options can be added later without breaking existing clients.
- **Startup:** the index loads in the background, so the API answers immediately with `starting` / 503 until it's ready.
- **Logs:** one JSON line per request, tagged with a request id. The chat metrics carry the same id.
